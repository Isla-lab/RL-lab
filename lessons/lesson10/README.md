# RL-Laboratory🤖 Lesson 10: PPO CleanRL Laboratory

This repository contains a Proximal Policy Optimization (PPO) laboratory based on the [CleanRL](https://github.com/vwxyzjn/cleanrl) framework. The code automatically adapts to both discrete and continuous action spaces using `gymnasium`.

This folder includes:
- `lesson10_cleanRL_ppo_train_code.py`: The template file with `# TODO` sections.
<!---	 - `ppo_cleanRL_solution.py`: The complete working solution. --->
- `lesson10_cleanRL_test.py`: A script to load and render the trained policy.

## Prerequisites

We recommend using **Python 3.10** or **Python 3.11**.
- On Windows, the command is usually `python` or `py`.
- On Unix/Linux/macOS, the command is usually `python3`.

## Setup Instructions

Please create a virtual environment to isolate the project dependencies. Ensure you use the provided `requirements.txt` file in this folder.

### Windows

1. Create the virtual environment:
   ```powershell
   python -m venv .venv
   ```
2. Activate the virtual environment:
   ```powershell
   .\.venv\Scripts\activate
   ```
   *(Note: if PowerShell blocks the execution, you might need to run `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` first).*
3. Install dependencies:
   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

### Unix / Linux / macOS

1. Create the virtual environment:
   ```bash
   python3 -m venv .venv
   ```
2. Activate the virtual environment:
   ```bash
   source .venv/bin/activate
   ```
3. Install dependencies:
   ```bash
   python3 -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

## Running the Training

You can train the agents on multiple environments defined in the repository scripts. The scripts will automatically loop through the environments and save the models (and learning curves) in the `runs/` folder.

### Windows
Run the batch script:
```powershell

.\lesson10_cleanRL_ppo_run_train.bat

```

### Unix / Linux / macOS
Make the script executable and run it:
```bash

chmod +x lesson10_cleanRL_ppo_run_train.sh

./lesson10_cleanRL_ppo_run_train.sh

```

*(Optional) You can also run the training manually for a single environment:*
```bash

python lesson10_cleanRL_ppo_train_code.py --env-id CartPole-v1 --total-timesteps 50000

```

**Note**: the number of total timesteps can be changed. This could be crucial for the correct training of some environments.

## Running the Tests

Once the training is complete, an output model file (e.g., `ppo_cleanRL_solution.cleanrl_model`) is generated inside the `runs/<environment_id>__<experiment_name>__...` directory.

To test and visually render the agent, use the `lesson10_cleanRL_test.py` script. Simply execute the following commands in your terminal (ensure your virtual environment is still active):

```bash

# Basic test command

python lesson10_cleanRL_test.py --env-id "CartPole-v1" --model-path "runs/CartPole-v1__ppo_cleanRL_solution__1__12345/ppo_cleanRL_solution.cleanrl_model"



# Test command with a specific number of episodes

python lesson10_cleanRL_test.py --env-id "CartPole-v1" --model-path "runs/CartPole-v1__ppo_cleanRL_solution__1__12345/ppo_cleanRL_solution.cleanrl_model" --episodes 10

```

*Important: Make sure to replace the dummy `runs/...` path with the actual path dynamically generated by your training job.*

# PPO Training Guide: Environment-Specific Setups

**Note**: Each environment requires a specific hyperparameter setup and training strategy for PPO to converge effectively. While basic environments can be solved quickly with default settings, more complex ones pose distinct challenges, such as sparse rewards or high-dimensional continuous action spaces.

Below is a practical guide for training various Gymnasium environments using the single-file CleanRL PPO implementation.

---

## 1. CartPole-v1 (Discrete)
* **Challenge:** Very simple dynamics with dense, immediate rewards.
* **Setup Suggestion:** Default PPO hyperparameters work perfectly. You only need a low number of total timesteps for the agent to easily reach the maximum score.
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id CartPole-v1 --total-timesteps 50000

```

## 2. LunarLander-v2 (Discrete)
* **Challenge:** The reward is dense and well-shaped, but balancing the lander requires finer control and planning compared to CartPole.
* **Setup Suggestion:** Increase the total timesteps. Implementing learning rate annealing (often on by default) and slightly lowering the initial learning rate is highly recommended to stabilize the final landing phase and prevent the policy from degrading.
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id LunarLander-v2 --total-timesteps 500000 --learning-rate 3e-4

```

## 3. Acrobot-v1 (Discrete)
* **Challenge:** The agent receives a -1 reward for every step until it reaches the goal height. It must learn to build momentum by swinging, requiring initial exploration.
* **Setup Suggestion:** Increase the entropy coefficient. Entropy in PPO encourages the agent to explore different swinging combinations before fossilizing into a suboptimal policy.
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id Acrobot-v1 --total-timesteps 300000 --ent-coef 0.05

```

## 4. MountainCar-v0 (Discrete)
* **Challenge:** **Severe Sparse Rewards.** The agent gets -1 per step and nothing positive until it hits the flag. Standard PPO relies on random actions initially and will likely never reach the flag by pure chance.
* **Setup Suggestion:** You must force the algorithm to "look further ahead" by drastically increasing the steps per rollout and maximizing initial random exploration. *(Note: If this still fails, modifying the environment via Reward Shaping is necessary).*
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id MountainCar-v0 --total-timesteps 1000000 --num-steps 1024 --ent-coef 0.1

```

## 5. MountainCarContinuous-v0 (Continuous)
* **Challenge:** Shares the exact same sparse reward problem as the discrete version, but the continuous action space makes hitting the target by random chance even more statistically improbable.
* **Setup Suggestion:** Use the same high-exploration parameters as the discrete version. **Warning:** Standard PPO usually fails here without direct code intervention (Reward Shaping) to guide the agent up the hill.
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id MountainCarContinuous-v0 --total-timesteps 1000000 --num-steps 2048 --ent-coef 0.1

```

## 6. Pendulum-v1 (Continuous)
* **Challenge:** The action space is continuous (applying exact torque values). The reward is dense, but precise balancing is required. Episodes are very short (200 steps).
* **Setup Suggestion:** Reduce the discount factor (`gamma`) to focus the agent on short-to-medium-term rewards, preventing the signal from being diluted over the short episode length.
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id Pendulum-v1 --total-timesteps 1000000 --gamma 0.90

```

## 7. BipedalWalker-v3 (Continuous)
* **Challenge:** Highly complex dynamics, a high-dimensional observation/action space (24 observations, 4 simultaneous continuous actions), and tricky local optima (e.g., learning to stand still to avoid falling penalties).
* **Setup Suggestion:** Requires millions of steps, extremely long rollouts, and larger batch sizes for stable updates.
```bash

    python lesson10_cleanRL_ppo_train_code.py --env-id BipedalWalker-v3 --total-timesteps 5000000 --num-steps 2048 --num-minibatches 32

```

* **MANDATORY CODE MODIFICATION:** The default CleanRL script uses small neural networks (`[64, 64]`). This does not provide enough capacity for a complex walking robot. In `lesson10_cleanRL_ppo_train_code.py`, inside the `Agent` class, **you must change the hidden layers from `64` to `256`**.
